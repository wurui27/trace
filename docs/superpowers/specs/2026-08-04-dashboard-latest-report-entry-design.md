# 主界面最新报告入口设计

## 目标

用户从桌面网页主界面直接打开最新一份可用的最终性能报告。入口必须读取当前团队的真实分析记录，不能写死分析编号，也不能使用演示数据替代。

## 界面

在“性能总览”标题区下方增加一条横向“最新分析报告”入口。它与现有页面的蓝灰色工具界面保持一致，不增加新的导航栏目。

入口展示：

- 分析状态和分析重点；
- SmartPerfetto 与 PerfPilot AI 的完成情况；
- 报告版本；
- 单一主操作“打开报告”。

点击主操作进入 `/analyses/{analysis_id}/report`。没有可用报告时，入口显示“还没有最终报告”，保留标题区已有的“新建分析”按钮，不添加重复操作。

本次只设计桌面网页。现有基础响应式规则可以保留，但不新增手机版布局和手机版验收范围。

## 数据接口

新增团队隔离的查询接口：

`GET /v1/teams/{team_id}/analyses?report_available=true&limit=1`

接口按创建时间倒序返回当前团队的分析摘要。每条摘要包含分析编号、状态、分析重点、报告可用状态、报告版本、SmartPerfetto 来源状态、三轮 AI 状态和创建时间。

本地运行时把创建时间写入现有分析状态文件。旧状态缺少创建时间时，优先使用报告生成时间；仍无法确定时使用稳定的最早时间，不伪造当前时间。生产接口沿用现有团队路由和租户数据库隔离规则。

## 前端数据流

新增独立的客户端组件 `LatestAnalysisReportEntry`：

1. 读取当前用户和团队；
2. 查询最新一份可用报告；
3. 校验响应；
4. 渲染真实报告入口。

组件只负责最新报告，不修改现有静态性能总览。后续将总览数据切换为真实接口时，可以独立替换，不影响报告入口。

## 状态处理

- 加载：显示与最终横条等高的骨架内容；
- 有报告：显示摘要和“打开报告”；
- 空状态：显示“还没有最终报告”；
- 请求失败：显示“暂时无法读取最新报告”，不展示旧报告或演示编号。

## 测试

- API 单元和集成测试验证团队隔离、过滤、排序、数量限制及旧数据恢复；
- 前端客户端测试验证列表响应校验；
- 组件测试验证加载、有报告、空状态和错误状态；
- 浏览器测试从主界面点击“打开报告”，确认进入真实报告路由；
- 完成后运行后端全量测试、前端单测、SSR 构建、ESLint 和 Ruff。
