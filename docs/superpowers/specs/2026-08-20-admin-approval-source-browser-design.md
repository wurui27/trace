# 管理后台、注册审核与远程源码目录设计

**日期：** 2026-08-20

**状态：** 已确认

**范围：** 本地账号注册与审核、Agent 申请与审核、管理员桌面端、远程源码目录浏览、分析中的源码匹配

## 1. 目标

本次改造解决四个问题：

1. 用户可以自助注册，管理员审核通过后才能登录。
2. 管理员可以集中审核账号和 Agent 申请。
3. 用户可以在网页中浏览远程 Agent 授权的源码目录，不再局限于固定工作区。
4. 系统在分析过程中读取并核对源码。源码不匹配时，Trace 和 SmartPerfetto 分析仍能完成。

系统必须保证：只有实际读取到匹配的源码内容，报告才能声称完成了源码分析。

## 2. 已确认的产品边界

### 2.1 首版包含

- 用户填写用户名、显示名称、密码和申请说明，自助提交注册申请；
- 管理员审核、拒绝、停用和重新启用普通用户；
- 普通用户申请 Agent，管理员审核后自动完成 Agent 注册；
- 管理员停用或删除 Agent；
- 管理员通过头像菜单进入专用后台；
- 用户在网页中浏览 Agent 授权源码根目录的子目录；
- 分析过程中读取 Manifest、Gradle 和源码文件，判断所选源码是否匹配测试包；
- 源码不匹配或不可读时，跳过源码分析并完成其他分析。

### 2.2 首版不包含

- 找回密码、邮件、短信和验证码；
- 后台提升普通用户为管理员；
- 管理员停用或删除自己；
- 操作记录页面；
- 浏览 Agent 的整台电脑；
- 自动修改、构建或提交用户源码；
- 源码不匹配时生成路径、symbol 或 Diff；
- 账号、Agent 或分析数据备份。

服务可以继续写脱敏运行日志，但产品不增加操作记录的数据表、接口或页面。

## 3. 角色与权限

### 3.1 平台管理员

现有 `is_platform_admin=true` 账号保留管理员身份。管理员可以：

- 查看全部注册申请；
- 审核或拒绝注册申请；
- 停用或重新启用普通用户；
- 查看全部 Agent 申请；
- 审核、拒绝、停用或删除 Agent；
- 进入 `/admin` 管理后台。

管理员不能通过后台创建新的管理员，也不能停用或删除自己。服务器必须在每个管理接口上检查管理员身份。隐藏前端入口不能替代服务端权限检查。

### 3.2 普通用户

普通用户只能访问自己的团队、Agent、源码工作区、设备、分析和报告。用户可以：

- 提交注册申请；
- 登录已启用账号；
- 申请、查看、重命名和删除自己的 Agent；
- 浏览自己 Agent 的授权源码根目录；
- 选择源码目录并开始分析。

普通用户不能查看其他用户的用户名清单、Agent、源码目录、设备、分析或报告。

## 4. 用户注册与审核

### 4.1 注册申请

登录页增加“注册账号”入口。表单包含：

- `username`：唯一用户名；
- `display_name`：显示名称；
- `password`：满足现有密码策略；
- `application_reason`：申请说明。

服务器收到申请后立即使用 Argon2 哈希密码。原始密码不得写入日志、响应或持久化文件。待审核申请会预留用户名，避免并发注册重复账号。

注册成功后，页面显示“申请已提交，等待管理员审核”。待审核用户不能进入应用。用户以正确密码尝试登录时，服务返回稳定的 `account_pending_approval`；被拒绝后返回 `account_registration_rejected`。错误响应不得包含密码哈希、内部路径或审核备注以外的服务端信息。

### 4.2 状态机

注册申请使用以下状态：

```text
pending -> approved
pending -> rejected
```

审核通过后，普通用户使用以下状态：

```text
active -> suspended -> active
```

`approved` 和 `rejected` 是注册申请的终态。`suspended` 属于已创建用户，不会退回注册申请。

### 4.3 审核事务

管理员批准申请时，服务器在同一持久化事务中完成：

1. 校验申请仍为 `pending`；
2. 创建用户；
3. 创建该用户的独立团队；
4. 建立用户与团队的一对一绑定；
5. 将申请标记为 `approved`。

任何一步失败都保留 `pending`，不能留下无团队用户或无用户团队。重复批准同一申请返回相同结果，不重复创建数据。

管理员停用用户时，服务器立即撤销该用户的全部会话。重新启用不会恢复旧会话，用户必须重新登录。

## 5. Agent 申请与审核

### 5.1 普通用户流程

普通用户在 Agent 页面点击“添加 Agent”后，服务器创建 `pending` 申请和一次性等待凭据。Agent 使用该凭据主动连接服务器，只能轮询审核状态。

待审核 Agent 不能：

- 注册设备；
- 获取采集任务；
- 获取源码任务；
- 浏览源码目录；
- 下载输入文件或上传分析产物。

管理员批准后，服务器将 Agent 绑定到申请人的团队，并通过现有等待连接自动下发正式凭据。Agent 无需重启，也不要求用户再次执行命令。

管理员自己添加 Agent 时，服务器直接批准。该行为仍经过同一注册与凭据生成逻辑，不能增加另一套旁路。

### 5.2 状态机

Agent 申请使用以下状态：

```text
pending -> approved
pending -> rejected
approved -> suspended -> approved
approved -> deleted
```

删除是终态。删除后，服务器立即撤销访问令牌、刷新令牌、租约和未完成任务。旧凭据不得再次连接。用户可以使用已经释放的显示名称创建新的 Agent 申请，但新申请必须获得新的 ID 和凭据。

### 5.3 重启与重试

等待审核的 Agent 可以在服务器或 Agent 重启后继续等待。批准、拒绝、停用和删除操作必须幂等。服务器在批准后、Agent 领取凭据前重启时，Agent 仍能领取同一组有效身份，不能生成两个 Agent。

## 6. 管理后台

### 6.1 入口与路由

管理员头像菜单增加“管理后台”。普通用户不显示该入口。直接访问 `/admin` 时，页面和 API 都必须校验管理员身份。

管理后台采用已经确认的蓝白桌面风格，只包含：

- 管理总览；
- 账号审核；
- Agent 审核；
- 返回 PerfPilot。

首版不显示操作记录。

### 6.2 管理总览

总览显示待审核账号数、待审核 Agent 数、已启用用户数和在线 Agent 数。下方按申请时间列出需要处理的账号和 Agent 申请。

### 6.3 账号审核

页面按“待审核、已启用、已停用、已拒绝”筛选，支持按用户名和显示名称搜索。管理员可以：

- 审核通过；
- 拒绝；
- 停用；
- 重新启用。

页面不显示密码、密码哈希、会话、令牌或内部存储字段。

### 6.4 Agent 审核

页面按“待审核、已连接、已停用、已拒绝”筛选，支持按 Agent 名称和申请人搜索。管理员可以：

- 批准并连接；
- 拒绝；
- 停用；
- 重新启用；
- 删除。

页面只显示安全的环境摘要，例如操作系统和架构。它不显示访问令牌、刷新令牌、主机绝对路径或源码路径。

## 7. 远程源码目录浏览

### 7.1 授权根目录

每个 Agent 在本机私有配置中声明一个或多个授权源码根目录。服务器只保存根目录的匿名 ID 和显示名称，不保存远程电脑的绝对路径。

网页只能浏览授权根目录及其子目录。浏览接口不能列出父目录、用户主目录、磁盘根目录或其他未授权目录。

### 7.2 通信方式

浏览沿用 Agent 主动连接服务器的模型：

1. 网页向服务器提交目录浏览请求；
2. 服务器创建短时、只读、团队绑定的目录任务；
3. Agent 领取任务并列出一层子目录；
4. Agent 返回目录名称、匿名节点 ID 和是否含有 Android 工程标记；
5. 服务器将闭合结果返回网页。

浏览器不直接连接 Agent。远程 Agent 不开放入站端口。

### 7.3 安全边界

Agent 使用目录文件描述符和 no-follow 规则逐级解析节点。以下输入必须拒绝：

- `..` 和绝对路径；
- 符号链接目录；
- 授权根目录被替换；
- 节点 ID 属于其他根目录、Agent 或团队；
- 非目录节点；
- 超过深度、数量、响应大小或超时限制的列表。

每个请求只列一层目录，并支持分页。建议首版限制为每页 200 个目录、闭合响应 128 KiB、任务有效期 30 秒。具体数值可以在实施计划中根据现有 Agent 合同上限校准，但不能取消边界。

### 7.4 工作区选择

用户选择目录后，服务器保存可复用的 `SourceWorkspaceBinding`。绑定包含团队、Agent、授权根 ID、匿名节点 ID、显示名称和版本，不包含绝对路径。

开始分析时，Analysis 只引用工作区绑定 ID。服务器和 Agent 必须再次校验绑定仍属于当前用户团队和当前 Agent。

## 8. 分析中的源码匹配

### 8.1 执行顺序

选择源码目录后，系统立即创建分析，不做提交前预检。源码检查作为正式分析阶段运行：

1. Agent 读取所选目录内的 Manifest、Gradle 配置和源码文件；
2. Agent 返回工程指纹、候选包名、启动类和可读源码文件数量；
3. 服务器将候选信息与分析请求中的测试包名、启动类和测试类型比较；
4. 匹配成功后，系统根据 SmartPerfetto 结论提取相关源码片段；
5. 服务器收到真实源码内容并校验哈希后，才生成源码根因和 Diff。

Agent 只能读取文本和元数据。它不得执行 Gradle、构建脚本、项目命令或用户源码。

### 8.2 匹配规则

分析请求中的测试包名是必填项。匹配按以下证据判断：

1. Gradle `applicationId` 精确匹配测试包名；
2. `namespace` 和 Manifest package 支持工程身份判断；
3. 自动启动测试的 Activity 能在 Manifest 或源码中解析；
4. 源码包结构与候选包名一致；
5. 至少读取到一个允许类型的真实源码文件。

系统解析文本，不执行 Gradle。存在 product flavor 或变量时，可以接受多个候选 application ID；至少一个候选必须精确匹配测试包名。模糊相似、目录名称相同或仅 namespace 相同不能替代 application ID 的精确证据。

### 8.3 结果状态

源码阶段使用以下公开状态：

- `available`：实际读取源码、匹配成功并取得可验证片段；
- `package_mismatch`：工程包名与测试包名不匹配；
- `activity_mismatch`：启动类不属于所选工程；
- `not_android_project`：缺少可识别的 Android 工程结构；
- `unreadable`：目录为空、权限不足或文件读取失败；
- `agent_unavailable`：Agent 离线或任务超时。

只有 `available` 可以发布相对路径、symbol、源码根因和 Diff。其他状态必须清空源码引用和 Diff。

### 8.4 报告表现

源码失败不把完整分析标记为失败或部分完成。Trace 和 SmartPerfetto 成功时，最终状态显示绿色“分析完成”。报告的源码区域单独显示：

> 所选源码与测试包不匹配，已跳过源码分析。Trace 与 SmartPerfetto 结论不受影响。

其他失败状态使用对应中文原因。报告不得声称读取了源码，也不得展示未经验证的路径、symbol 或 Diff。

## 9. 持久化与合同

### 9.1 控制数据

首版复用现有私有本地控制仓库，不引入外部数据库。控制仓库增加闭合、带版本的注册申请集合；Agent 仓库增加闭合、带版本的审核状态和等待凭据摘要。

密码、会话和凭据继续使用摘要或哈希存储。所有状态文件保持现有 0700 目录、0600 文件、跨进程锁、原子替换、fsync、no-follow 和根目录固定规则。

用户、团队、注册申请、Agent 申请和授权根元数据跨服务器重启保留。分析数据清理不得删除这些控制数据。系统不创建备份文件。

### 9.2 主要合同

新增或扩展以下闭合合同：

- `RegistrationApplication`；
- `AdminUserSummary`；
- `AgentApplication`；
- `SourceRootSummary`；
- `SourceDirectoryPage`；
- `SourceWorkspaceBinding`；
- `SourceMatchResult`。

所有合同拒绝未知字段、绝对路径、令牌、远程 URL、命令参数和私有存储坐标。分页游标、节点 ID、申请 ID 和绑定 ID 使用不可预测的随机标识，并绑定团队和对象身份。

### 9.3 接口范围

预计新增以下接口族：

- `/v1/auth/register`；
- `/v1/admin/registration-applications`；
- `/v1/admin/users`；
- `/v1/admin/agent-applications`；
- `/v1/teams/{team_id}/agents/{agent_id}/source-roots`；
- `/v1/teams/{team_id}/agents/{agent_id}/source-browser/list`；
- `/v1/teams/{team_id}/source-workspaces`。

具体方法和请求模型在实施计划中对齐现有客户端命名。所有写接口沿用现有会话、CSRF 和团队权限校验。Agent 控制接口沿用签名快照、团队围栏和租约验证。

## 10. 兼容与迁移

- 现有用户迁移为 `active`；
- 现有平台管理员保持管理员身份；
- 现有已注册 Agent 迁移为 `approved`；
- 现有已撤销 Agent 保持失效；
- 现有源码工作区继续可读，并逐步转换为匿名授权根绑定；
- 现有 Analysis 1.0 和 1.1 请求继续读取；新建远程源码绑定使用新合同；
- 旧报告保持可读，不重新推断源码匹配状态。

迁移必须幂等。服务器在迁移失败时拒绝启动管理写入，不能静默丢弃用户或 Agent。

## 11. 错误处理与并发

服务对外使用稳定错误代码：

- `account_pending_approval`；
- `account_registration_rejected`；
- `account_suspended`；
- `agent_pending_approval`；
- `agent_registration_rejected`；
- `agent_suspended`；
- `source_root_unavailable`；
- `source_directory_out_of_scope`；
- `source_workspace_mismatch`；
- `source_workspace_unreadable`。

错误正文不包含绝对路径、密码、哈希、令牌、命令、设备序列号或其他团队信息。

审核、停用、删除、目录注册和工作区创建必须使用对象版本或等价的比较并交换语义。两个管理员并发处理同一申请时，只允许一个状态转换生效；另一个请求返回当前终态。服务器不能创建重复用户、团队、Agent 或工作区。

## 12. 验收标准

自动化测试和桌面端验收必须覆盖：

1. 新用户提交注册后无法登录，管理员批准后可以登录并只看到自己的团队；
2. 管理员拒绝注册后，用户收到稳定状态，密码和内部信息不泄漏；
3. 普通用户访问任一管理页面或管理 API 均返回 403；
4. 管理员无法停用或删除自己，也无法提升其他管理员；
5. 两个并发批准请求只创建一个用户和一个团队；
6. 用户停用后，现有会话立即失效，重新启用后必须重新登录；
7. 普通用户 Agent 等待审核时可以保持连接，但不能获取任何设备、源码或分析任务；
8. 管理员批准 Agent 后，Agent 无需重新运行命令即可自动连接；
9. Agent 停用或删除后，旧令牌、刷新令牌、租约和任务全部失效；
10. 用户 A 不能查看或处理用户 B 的 Agent 申请、设备、目录、分析或报告；
11. 网页可以逐层浏览在线 Agent 的授权源码根目录；
12. `..`、绝对路径、符号链接、根目录替换、跨根节点和跨团队节点全部被拒绝；
13. 用户选择目录后立即开始分析，源码匹配在分析阶段运行；
14. 匹配的 `applicationId`、Activity 和源码产生 `available`，并生成有真实内容哈希的源码引用和 Diff；
15. 包名、Activity 或工程不匹配时，Trace、SmartPerfetto 和中文总结继续完成；
16. 源码不匹配的最终分析显示绿色“分析完成”，并显示明确的源码跳过提示；
17. 源码失败报告不包含路径、symbol、源码引用或 Diff；
18. Agent 在目录浏览或源码读取期间离线时，系统使用稳定降级状态，不让分析永久卡住；
19. 服务器和 Agent 重启后，待审核用户、待审核 Agent、已批准 Agent 和源码工作区状态保持一致；
20. 分析数据清理不删除用户、团队、Agent 申请或源码根配置；
21. 登录、注册、审核和目录浏览页面保持确认的蓝白桌面风格；
22. 登录页不出现找回密码，管理后台不出现操作记录。

## 13. 实施顺序建议

实施计划应按以下依赖顺序拆分：

1. 注册申请数据模型、状态机和管理员权限；
2. 注册接口、登录门禁和账号审核接口；
3. Agent 审核状态机、等待连接和凭据下发；
4. 蓝白管理后台与头像入口；
5. Agent 授权根配置和目录浏览协议；
6. 网页目录选择与工作区绑定；
7. 分析中的包名、Activity 和源码内容匹配；
8. 报告降级状态、跨重启恢复和端到端验收。

每一步必须先增加失败测试，再实现最小闭环。不得在账号或 Agent 审核尚未具备团队隔离时开放远程目录浏览。
